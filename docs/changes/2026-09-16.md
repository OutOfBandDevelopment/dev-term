- **A decimal/hex display toggle for HID Vendor/Product ID**, the next Connection Editor Architect
  Notes item picked up. `HidVendorId`/`HidProductId` stay canonical decimal strings always — what
  `BuildOptions`/`LoadIntoFields`/`SelectedHidDevice` all read and write, unchanged — and a new
  `HidIdsShowHex` bool plus two new `HidVendorIdDisplay`/`HidProductIdDisplay` properties handle the
  actual decimal↔hex conversion (4-digit uppercase, no `0x` prefix, matching `--listhiddevices`'s own
  `"046D:C08B"` formatting); an unparseable value is stored as-is rather than blanked, the same
  "don't reject a keystroke, let validation catch it later" behavior every other typed field already
  has.

  A real WPF data-binding hazard shaped the design, caught before writing any code rather than
  discovered by a flaky test: a `TextBox` bound bidirectionally to a property that reformats on
  every change would have its text reformatted (and its caret reset to the end) after *every single
  keystroke*, since `UpdateSourceTrigger=PropertyChanged` means the setter runs, and if that setter
  also re-raised its own property's change notification, WPF would immediately re-pull and rewrite
  the `Text` it just set. Fixed by never having `HidVendorIdDisplay`/`HidProductIdDisplay`'s own
  setter re-raise their own change notification — only `HidVendorId`/`HidProductId` (for callers
  bound directly to those, and dirty-tracking) — and only re-raising the `*Display` properties from
  elsewhere: `HidIdsShowHex`'s setter (toggling the checkbox) and `HidVendorId`/`HidProductId`'s own
  setters (Load, the detected-devices picker). The TUI has no continuous binding to fight the same
  way, but needed its own investigation: confirmed via a headless probe against the installed
  Terminal.Gui v2.5.0 package that `CheckBox.Activated` fires *after* `Value` has already flipped
  (and that `Command.Activate`, bound to Space, is what actually toggles a `CheckBox` — `Accept`
  isn't wired to that at all), so the new "Show as hex" checkbox's handler pushes the currently-typed
  text through the view model's *old* format first, then updates `HidIdsShowHex`, then pulls the
  reformatted text back out — reinterpreting what's already there instead of misreading it.

  Both front ends' HID labels dropped "(decimal)" (no longer accurate) and gained the checkbox.
  Adding a new TUI row surfaced the same kind of one-off layout arithmetic mistake as the Browse
