
## UX decision interview

Eight open design questions answered by the owner and struck in their source docs, with the implementation work listed in BACKLOG.md "UX decisions awaiting implementation": plugin panels filter by presenter (disabled with a reason), control panel section state per profile, async plugin rendering, theme delete button, session pipe name = profile name plus `--listsessions`, one discovery row per device with service badges, interlocked controls visible but disabled, live notes in a recording log. Also: automated screenshot tests for the TUI and WPF plugin approval prompts (`PluginApprovalDialogTests` in both test projects).

Four more answered in a second round: Stream Monitor gets one pane per device, RFC 2217 line state goes to the status line and log only, indicators carry a format/unit hint, and the CLI scripts across sessions by attaching to a named session. Listed in BACKLOG.md with the others.

A third round answered four more: network config editors are manifests with a config UI where possible, schemas get a stable hosted URL, a UDP listener is one session showing each sender, and raster export is a core service. Listed in BACKLOG.md.

A fourth round: plugin reply timeout defaults to 2 s and plugins ship as a zip installed from the Plugins screen, SCPI profiles stay separate but layered (generic plus device sub-types), and a TCP listener opens one tab per peer. Listed in BACKLOG.md.

A fifth round: playback gets checkpoints, a skip-silence cap and revisioned note edits, and manifest commands declare an expected response format. Listed in BACKLOG.md.

A sixth round (known gaps in shipped screens): `--capture <dir>` for the Stream Monitor, expression picker parameter fields first, manifest editor JSON-only with an XML convert, a scroll marker on the TUI theme role list. Listed in BACKLOG.md; the gap lines in OPEN_QUESTIONS.md stay until each is built.

## Theme delete

The seed picker has a Delete button (TUI and WPF) that confirms and removes a saved theme via `ThemeCatalog.Delete`; built-ins refuse. Covered by `ThemeTests.Delete_RemovesOnlyTheNamedUserThemeFile_AndReportsAnUnknownName`.

## Theme role list position

The TUI theme builder shows an `n / total` marker beside the role list (`PositionLabel`); covered by `ThemeBuilderModeTests.RoleList_ShowsItsPositionAsTheSelectionMoves`.

## Interlocked controls

`UiControl.EnabledWhen` + `DisabledReason` (schemas regenerated): control panels keep the row visible but disabled until the condition holds. WPF shows the reason as a tooltip (`ToolTipService.ShowOnDisabled`), the TUI as a note after the row. Covered by `Control_EnabledWhen_*` in `ControlPanelModeTests` and `ControlPanelWindowTests`. The web panel does not honor it yet.

## Section state persists

`SectionExpansionState.UsePersistence` (called at console and WPF startup) saves collapsed control-panel sections to `~/.dev-term/section-state.json` and reloads them, keyed by the panel's definition name (one per device/SCPI profile). Tests never enable it, so they don't touch the user's home. Covered by `SectionExpansionStateTests.UsePersistence_*`.

## Notes in a live recording

`SessionLogger.RecordNote` writes a timestamped `note` record into the log being recorded, in sequence with the traffic. File > Add Note to Log... (TUI prompt, WPF dialog) is enabled only while the active tab logs. Covered by `SessionLoggerTests.RecordNote_*`, `TuiLoggingTests.AddNoteMenuItem_*` and `PlaybackWindowTests.MainWindow_AddNoteToLog_*`. Web and CLI have no entry point yet.
