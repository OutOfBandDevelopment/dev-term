# 2026-09-14

## Completed

- Scaffolded the solution: `DevTerm.Core`, `DevTerm.Transports.Serial`, `DevTerm.Presenters.Text`,
  `DevTerm.Console` (CLI mode), plus one MSTest+Moq test project per src project. .NET 10,
  dependency injection via `Microsoft.Extensions.DependencyInjection`/Generic Host throughout.
- `DevTerm.Core`: `ITransport`, `IPresenter`/`IPresenterInput`, `Pipeline`, `PresenterCatalog`,
  `Session`/`ISessionFactory`, DI registration (`AddDevTermCore`).
- `DevTerm.Transports.Serial`: `SerialTransport` over an `ISerialPort`/`ISerialPortFactory`
  abstraction so tests never touch real hardware; `SerialTransportOptions` via the Options pattern.
- `DevTerm.Presenters.Text`: ASCII, UTF-8, hex, decimal, octal, binary presenters.
- `DevTerm.Console`: CLI mode wired through `Host.CreateDefaultBuilder`/DI.
- Discovered and fixed a real constraint: Moq/Castle cannot mock a method taking
  `ReadOnlySpan<byte>` (ref struct) — switched `IPresenter.Render` to `ReadOnlyMemory<byte>`
  at the interface boundary.
- Added `DevTerm.Transports.Tcp`: `TcpTransport` supporting both Client (dial out) and Listener
  (accept one peer) modes, same testable-adapter pattern as Serial; custom
  `IValidateOptions<TcpTransportOptions>`.
- Wired TCP into the console CLI (`--transport serial|tcp`, mode-specific args); verified with a
  manual loopback smoke test (client -> listener, decoded correctly). Resolved a
  `docs/design/transports.md` open question: v1 TCP listener policy is one-peer-at-a-time.
- Converted the design docs' architecture diagrams to standard C4-PlantUML notation, and added
  `docs/design/device-control-modules.md` for plugins that combine active control (commands to
  send) with telemetry decode/present/plot.
- 71 unit tests passing across all projects (no hardware, no real sockets in the test suite).

- Switched `DevTerm.Console` CLI argument handling from a hand-rolled parser to
  `Microsoft.Extensions.Configuration.CommandLine` + the Options pattern: command-line args
  bind onto a `CliOptions` class (property names double as argument names), validated via a
  `CliOptionsValidator : IValidateOptions<CliOptions>`. Removed `CliArguments`/`CliArgumentsTests`
  entirely. Tests now exercise the real `ConfigurationBuilder().AddCommandLine(...)` binder
  instead of hand-rolled parsing semantics, which also surfaced a real quirk worth knowing:
  the provider has no bare-boolean-flag support — `--listen` needs an explicit value
  (`--listen true`), not a bare switch.
- 70 unit tests passing across all projects.
