# 2026-10-14

## Listing live sessions

`--listsessions true` prints the sessions publishing on a `--pipe` (`SessionPipeServer.LiveSessions` enumerates `\.\pipe\devterm-session-*`; Windows only, empty elsewhere). A second process asking for a name already in use now gets `name-2`, `name-3`, ... (`AvailableName`) instead of failing to bind; applied in the CLI, TUI and WPF. Covered by `SessionPipeServerTests.LiveSessions_*` and `AvailableName_*`. `--pipe true` now names the pipe after the matching saved profile, else the transport (`Resolve`); the CLI prints the final attach name.

## `--capture <dir>` in the CLI

`CliOptions.Capture`: the CLI attaches a `StreamMonitor` to its session, saves detected streams into the folder and prints each `Captured ... to ...` line. Covered by `CliModeCaptureTests`. TUI and WPF keep their monitor windows.

## Manifest commands declare `ExpectedResponseFormat`

`OutboundCommand.ExpectedResponseFormat` (default `Text`, written by name) lets a device manifest command say its reply is an image, HP-GL, etc. `ManifestControlSurface.InvokeAsync` calls `ExpectResponse` on the session's `IStreamContentHintSink` presenters just before sending, same as `ScpiControlSurface`; nothing happens when no Stream Monitor is running. `schemas/device-manifest.schema.json` regenerated. Covered by `ManifestControlSurfaceTests.InvokeAsync_CommandDeclaringAResponseFormat_*` and `ExpectedResponseFormat_IsWrittenByName_AndReadBack`.

## Indicator `Format` and `Unit`

`IndicatorControl.Format` (.NET numeric format; `X2` shows the value as hex) and `Unit` shape the displayed text through `IndicatorControl.Display`; text with no number, or an invalid format, is shown as published. The TUI, WPF and web panels call it for directly published values, and `IndicatorState.Text` applies it to an expression's result, so charts and thresholds still see the raw number. Covered by `IndicatorStateTests.Display_*` and `Text_AppliesTheIndicatorsFormatAndUnit`; `ui-definition` and `device-manifest` schemas regenerated.

## RFC 2217 line and modem state on the status line and in the log

`Rfc2217Transport` now asks the server for modem-state and line-error notifications on open (`SET-MODEMSTATE-MASK` 0xFF, `SET-LINESTATE-MASK` overrun/parity/framing/break) and raises them through the new `ILineStatusSource.LineStatusChanged`; `Session.LineStatusChanged` re-raises it. Texts come from `Rfc2217StatusText` (`Modem lines: CTS on, DSR off, RI off, DCD off`, `Line error: parity`); identical consecutive modem texts are suppressed. TUI and WPF append them to the output as status lines, the CLI writes them to stderr, and `SessionLogger` records a `[line] ...` note. They never enter the data stream or presenters. The web front end is not wired yet. Covered by `Rfc2217TransportTests.ModemStateNotification_*`, `StatusText_*`, `SessionTests.LineStatusChanged_*` and `SessionLoggerTests.ALineStatusNotice_*`.

## Plugin panel entries filter by the selected presenter

`DevicePanels.UnavailableReason(panel, options, connected)` returns why a contributed panel is disabled: not connected, connection does not suit it, or its feeding `PresenterName` is not among the connection's selected presenters (`Select the 'k8055' presenter to use this panel.`). The TUI puts the reason in the item's help text and WPF in its tooltip; the item stays visible. Web not changed. Covered by `MainWindowStateTests.UnavailableReason_*` and `MainWindowConnectionStateTests.AK8055Connection_WithoutTheK8055Presenter_*`; the two K8055 enable tests now select the `k8055` presenter.

## Out-of-process plugins render asynchronously

New `IAsyncOutputSource` (`OutputReady`): a presenter that answers later. `LazyExternalPresenter` now returns from `Render` at once, queues chunks to one worker (start on first use, ask, deliver in order), and `Pipeline.AsyncOutput` -> `Session.Output` carries the lines, so a slow or hung plugin no longer stalls the read loop or other presenters (it still faults after its reply timeout, default 2 s). `FlushAsync` waits for queued work (tests, shutdown). `ExternalProcessPresenter` itself is unchanged (synchronous). Covered by `PluginTrustTests.TheLazyPresenter_RenderReturnsAtOnce_*`; the two existing lazy-presenter tests now flush first.

## Hosted `$schema` URL

Schemas are served from the repo's `schemas/` folder on GitHub raw. `SchemaGenerator.BaseUrl` plus the file name is each schema's `$id` (regenerated). A manifest, UI definition or profile can reference `https://raw.githubusercontent.com/OutOfBandDevelopment/dev-term/main/schemas/device-manifest.schema.json` as its `$schema`; swap `main` for a release tag to pin. Covered by `SchemaDriftTests.EverySchema_HasAnIdThatIsItsHostedUrl`.

## Discovery: one row per device with service badges

`NetworkDiscovery.GroupByDevice` groups merged hits by address into `NetworkDevice` (name, hostname, one service per transport/port). `--listnetworkdevices` prints `address  name  [badges]`; the web Connections page shows a row per device with a button badge per service that prefills it. The TUI/WPF pickers still list one entry per service. The `connecting.md` transcript lines were converted from the earlier real capture to the new format (not recaptured; no devices attached). Covered by `NetworkDiscoveryTests.GroupByDevice_*`.

## Stream Monitor: one pane per device

`StreamCaptureView.Panes` returns an all-devices pane plus one pane per device with its capture count. WPF replaces the device drop-down with a row of device tabs; the TUI gains a `Device:` button that cycles the same panes (search field narrowed to 16 columns to fit). A pane that empties (its captures aged out) falls back to all devices. The monitor itself already tracked several sessions at once. Covered by `StreamCaptureViewTests.Panes_*`, `StreamMonitorWindowTests.FilterSearchAndSort_*` and `StreamMonitorModeTests`; Stream Monitor screenshots regenerated.

## CLI: attach to a named session, then the REPL

`--attach <name> --cli true` (`AttachCliMode`) is an ordinary stdin REPL against another process's session started with `--control <name>`: a typed line goes through `send` (the host's parser and line ending), `:hex AA BB` sends raw bytes, `:ping` checks the session, `:quit` leaves, `::text` sends a line beginning with a colon. Traffic prints with the ASCII beside it. No such session exits 1 with the `--control` hint. Plain `--attach` stays the read-only tail. Tests: `AttachCliModeTests` (line mapping; a real control pipe server; missing session).
