## Applied queued SystemUsbtmcDevice code-review findings

Applied the four `SystemUsbtmcDevice` code-review findings queued in commit `1897ce4` (filed in
`docs/design/usbtmc-transport.md`'s "Open questions" section, deliberately deferred pending the
USBTMC bulk-IN stall investigation which is still parked): endpoint selection now filters transfer
type (`Attributes & 0x03 == 0x02`, Bulk) in addition to direction, so an optional Interrupt-IN
endpoint (USB488 SRQ) can no longer be mistaken for bulk-IN; `SetRemote`'s `wValue` is now always
`0` per the USB488 subclass spec instead of `remote ? 1 : 0`; `TryGetSerialNumber`'s swallowed
exception is now logged via `Debug.WriteLine`; and `Open()`'s failure-path catch now explicitly
calls `ReleaseInterface` before `Close()`/`Dispose()`. No behavior change expected against real
hardware already working (Rigol DM3058E's bulk-IN endpoint was already sorting first in its
descriptor), verified via a clean full-solution build and a full passing `TestCategory=UNIT` run;
not re-verified against real hardware this pass, since the parked stall issue means the DM3058E
still can't complete a query round-trip to confirm end-to-end. See
[`docs/design/usbtmc-transport.md`](../design/usbtmc-transport.md) for the updated findings detail.
