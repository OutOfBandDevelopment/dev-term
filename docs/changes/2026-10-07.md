# 2026-10-07

Open-question interview with the owner. Decided: project files should also hold send history, log settings and window layout; RFC 2217 server mode is wanted as a TCP listener proxy (not a virtual serial port); named `--profile <name>` profiles yes, plugin-options namespacing no; the read-write control channel and out-of-process plugins go over both a named pipe and a localhost web service. Source docs, BACKLOG and OPEN_QUESTIONS updated; no code changed.

## Named profiles

`--profile <name>` (`CliOptions.Profile`) now starts a run from a saved connection profile: `DevTermConfiguration.AddNamedProfile` layers it above `appsettings.Local.json` and below the project layer, environment variables and flags. The console app exits with "No saved connection profile named ..." for an unknown or invalid name. Test: `ProjectFileTests.ProfileFlag_LayersTheNamedSavedProfile_UnderCommandLineFlags_AndIgnoresAnUnknownOne`. Docs: connection-profiles design, managing-profiles guide.

## TCP share proxy

`--sharetcp <port> [--sharebind <ip>]` (CLI mode) shares the live session on a TCP port: `SessionTcpShareServer` is a session observer that copies device bytes to the one connected client and writes the client's bytes to the device via `Session.SendAsync`; a second client is closed at once; loopback by default. This is the proxy half of the RFC 2217 server decision; RFC 2217 negotiation is not built. Tests: `SessionTcpShareServerTests` (real loopback socket), `CliOptionsValidatorTests.ShareTcp_*`. Checked end to end with `--transport loopback` and a raw TCP client. Not in the TUI/WPF yet.

## Project files keep send history, log setting and the active tab

`ProjectFile.FromTabs` (with `ProjectTabState`) captures each open tab's send history, whether it was logging (`Log`: `true` for an automatic file, or the tab's explicit `--log` path) and the front tab (`Active`); `ProjectConnection` gained optional `History`/`Log`, `SendHistory.Restore` reloads history. TUI and WPF Save/Open Project use them; reopening restores history, restarts logging (WPF via `StartLoggingFromOptions`, TUI via the tab's `Log` option) and re-selects the front tab. Tests: `ProjectFileTests.FromTabs_*`, `SendHistory_Restore_*`. Not driven by an automated test through the native file dialogs. Window size/position is not saved.

## Read-write control pipe (`--control <name>`)

`SessionControlPipeServer` (`DevTerm.Core.Sessions`): a duplex named pipe `devterm-control-{name}` created with `PipeOptions.CurrentUserOnly`, so only the same OS user can connect. Commands, one per line: `send <text>` (encoded by the host with `TypedInput.TryEncode`, so parser and line ending apply), `sendhex <HEX>`, `ping`; each gets `ok` or `error <why>`. It is also an `ISessionObserver`, so `open`/`rx HEX`/`tx HEX`/`closed ...` lines stream on the same pipe. Sends go through `Session.SendAsync`, so they interleave with the front end's own typing. Console CLI mode only for now. Test: `SessionControlPipeServerTests` (Integration, real local pipe). The localhost web-service variant is still open.

`--control <name>` now also works in the TUI and WPF (first tab's session only), encoding `send` text with the default parser. Not covered by a front-end test.

`--controlclient <name>` (`SessionControlClient`): reads control commands from stdin, prints replies and events. Checked across two real dev-term processes (loopback transport): `ping`, `send hello`, `sendhex 41 42` returned `ok`, with the matching `tx`/`rx` lines. A host that ends mid-run no longer crashes the client. Test: `ControlClient_SendsCommandsAndPrintsReplies`.

`--controlhttp <port>` (`SessionHttpControlServer`, `HttpListener` on 127.0.0.1 only): the localhost web-service twin of the control pipe. Every request needs a bearer token (`Authorization: Bearer ...` or `?token=`); it is random per run and printed by the CLI, or fixed with `--controltoken` (the TUI and WPF have nowhere to print one, so set it there). `POST /command` takes the same `send`/`sendhex`/`ping` lines and answers `200 ok` or `400 error ...`; `GET /events` is Server-Sent Events with the `open`/`rx`/`tx`/`closed` lines; no CORS headers are sent, so another origin cannot drive the device. The command executor moved to a shared `SessionCommands` used by both servers. Test: `SessionHttpControlServerTests` (401 without the token, commands reach the transport, `tx` event arrives). Not run against a browser.

Out-of-process plugins that outlive the host: no new host code, since the control pipe and `--controlhttp` already let any program tail events and send. Added `examples/python/control-channel-client/echo_bot.py` and ran it against a loopback session: `ping` ok, `tx`/`rx`/`closed` events streamed. The reply-to-`rx` path was not exercised in that run.

`--sharerfc2217 true` (with `--sharetcp`): `Rfc2217ServerBridge` makes the share port an RFC 2217 server. Checked with pyserial 3.5 over `rfc2217://127.0.0.1:2217` against a loopback session: connect, DTR/RTS off, baud 19200 acknowledged, `hello` sent and the reply read. Requested settings are recorded and acknowledged, not applied to the device. Test: `Rfc2217ServerBridgeTests` (Integration, real socket). CLI mode only so far.
