# 2026-10-08

Project files: `ProjectFile.Window` (`ProjectWindowBounds`) stores the WPF main window's position, size and maximized state on **File > Save Project**, restored on **Open Project** unless it would land off-screen or below the minimum size. Older files without it load unchanged. Test: `ProjectFileTests.RoundTrip_KeepsTheWindowBounds_AndOldFilesWithoutThemStillLoad`. The BACKLOG line for history/log/active tab was stale (already built 2026-10-07) and is corrected. Not driven through the real file dialogs.

`DevTerm.Web` honors `--controlhttp <port>`/`--controltoken` (`WebHost.Built.ControlHttp`): the same loopback command/event channel on the web host's shared session, with its own bearer token, printed at startup. Test: `WebHostTests.ControlHttp_SendsToTheSharedSession_AndNeedsItsOwnToken`. Extra project connections opened through `/api/connections` are not covered.

`DevTerm.Web` `GET /api/devices` (token required): serial ports plus USB HID and USBTMC devices attached to the host, from the same discovery the Connection Editor uses; a discovery failure yields an empty list for that kind. Test: `WebHostTests.ApiDevices_RequiresTheTokenAndReturnsTheThreeLists`.

`DevTerm.Web` `GET /api/events` (token required): a Server-Sent Events stream of `connection-opened`, `connection-closed` and `line` events (`HostEvents`; per-subscriber bounded queue that drops the oldest). Tests: `HostEventsTests`, `WebHostTests.ApiEvents_StreamsConnectionOpenedAndClosed`.

Docs: `docs/specs/web-terminal.md` now lists `/api/project`, `/api/connections`, `/ws/{id}`, `/api/devices`, `/api/events` and `--controlhttp`; `docs/user-guide/web-terminal.md` has a section with the captured output of each call. The Blazor connections UI, when built, adds its own spec and screenshots there.

`DevTerm.Web` `/connections` Blazor page: lists the project connections and the open ones, with Open/Close buttons; read-only tokens see it disabled. The open-connection set moved from `WebHost` into `ConnectionManager` so the REST endpoints and the page share it. Tests: `WebScreenshotTests.ConnectionsPage_OpenAndClose_Screenshot`, `ConnectionsPage_ReadOnly_DisablesTheButtons`.

`DevTerm.Web` API docs: `/openapi/v1.json` (Microsoft.AspNetCore.OpenApi), `/scalar/v1` (Scalar.AspNetCore) and a hand-written `/asyncapi.json` for `/ws`, `/ws/{id}` and `/api/events`. `/api/events` does not appear in the OpenAPI document (a stream-only Task handler is skipped by the generator), so AsyncAPI is where it is described. Test: `WebHostTests.ApiDocs_OpenApiScalarAndAsyncApi_AreServedBehindTheToken`.

`DevTerm.Web` project editing: `PUT`/`DELETE /api/project/connections/{name}` (`ConnectionManager.Upsert`/`Remove`) add, replace and remove connections in the `--project` file, validating the profile JSON with `CliOptionsValidator` and publishing a `project-changed` event. A live run against a loopback host showed a project file with the wrong schema giving a 500; both methods now report an unreadable file as a 400 (Upsert) or 404 (Remove). Test: `WebHostTests.ApiProject_PutAndDeleteAConnection_EditsTheProjectFile`.

DELETE endpoints (`/api/connections/{id}`, `/api/project/connections/{name}`) are idempotent: 204 whether or not the target existed, 403 only for a read-only viewer. `DevTerm.Web` also starts with no connection arguments (previously exited with "Missing required --port"); verified live with only `--project`, opening a connection through `POST /api/connections`.

Added `docs/specs/session-control-channel.md` (flags, command set, events, limits for `--pipe`/`--attach`/`--control`/`--controlclient`/`--controlhttp`), checked against `SessionCommands` and `Program.cs`.

Added `/asyncapi`, a dependency-free page (no CDN) that renders `/asyncapi.json`; screenshot captured from a running host in headless Edge (`docs/user-guide/images/web-asyncapi-viewer.png`). This closes the AsyncAPI-viewer open question.

Added a "Proposals and bugs tracker" to `BACKLOG.md` (one row per proposal with unchecked checklist items, plus an open-bugs line; none open), a "Next interview round" block to `OPEN_QUESTIONS.md`, and the rule to `CLAUDE.md` and the `work-docs-audit` skill so the tracker stays current.
