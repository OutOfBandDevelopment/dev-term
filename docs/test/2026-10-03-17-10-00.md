# 2026-10-03 17:10: K8055 loop-back between two boards

Two Velleman K8055 boards wired together so one drives and the other reads: no hands needed. Follow-up to `2026-10-03-14-42-02.md`, which had nothing wired.

## Bench topology

Board 0 (PID 0x5500, HID VID 0x10CF/PID 21760) is the driver; board 3 (PID 0x5503, 21763) is the reader.

| Board 0 output | Board 3 input |
|---|---|
| digital out 1 | digital in 1 |
| digital out 2 | digital in 2 |
| DAC (analog out) 1 | analog in 1 |

Both boards enumerated (`--listhiddevices`: `10CF:5500`, `10CF:5503`).

## Commands

```bash
# reader (board 3), background
dotnet run --project src/DevTerm.Console --no-build -- --transport hid --vendorid 4303 --productid 21763 --presenter hex --parser hex --lineending None --cli true
# driver (board 0), one line every 2.5 s
dotnet run --project src/DevTerm.Console --no-build -- --transport hid --vendorid 4303 --productid 21760 --presenter hex --parser hex --lineending None --cli true
```

Driver lines (9-byte report: report id `00`, command `05`, digital mask, DAC1, DAC2, four zero bytes):
`00 05 01 00 00 00 00 00 00`, `... 02 ...`, `... 03 ...`, `... 00 ...`, then `00 05 00 80 ...`, `00 05 00 FF ...`, `00 05 00 00 ...`.

## Results (board 3 input report, in order of the runs seen)

| Sent by board 0 | Board 3 digital byte (byte 1) | Board 3 analog 1 (byte 3) |
|---|---|---|
| digital out 1 on (`01`) | `10` | `00` |
| digital out 2 on (`02`) | `20` | `00` |
| both (`03`) | `30` | `00` |
| all off | `00` | `00` |
| DAC1 = 128 (`80`) | `00` | `14` (20) |
| DAC1 = 255 (`FF`) | `00` | `29` (41) |
| DAC1 = 0 | `00` | `00` |

## Findings

- **Digital input mapping confirmed for I1 and I2:** I1 = `0x10`, I2 = `0x20`, and they combine (`0x30`). The earlier hand presses on board 0 showed the same two values.
- **Byte 2 tracks the board address:** `0x01` on PID 0x5500, `0x03` on PID 0x5502 (2026-09-15), `0x04` on PID 0x5503 here, so it reads as address + 1. Three boards, one consistent rule.
- **DAC to ADC is linear but scaled:** 128 reads 20 and 255 reads 41 (about 0.16). Unexplained; the wiring (a divider, or a different analog range) may be the cause, or the DAC and ADC ranges differ. Not caused by dev-term, which only passes the bytes through.
- The timestamps first logged were wrong (a pipe buffered the reader); the table above is from run order, not timing.
- I3 to I5, the pulse counters and the trailing two Set bytes were not exercised.
- Both boards were left with outputs off and DAC at 0.

## Summary

No code change. Answers the digital-in mapping (I1, I2) and the "constant byte 2" questions.
