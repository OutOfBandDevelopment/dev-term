# 2026-10-03 14:42: K8055 and Zoom H4n read/write pass

Follow-up to the K8055 raw-write error ("Operation failed early: The parameter is incorrect.") and a live check of the Zoom H4n remote port. Both were authorised for read and write.

## Device matrix

| Device | Transport / address | Framing | Result |
|---|---|---|---|
| Velleman K8055 (PID 0x5500) | HID, VID 4303 (0x10CF) / PID 21760 | hex presenter, hex parser, **`--lineending None`** | confirmed working; raw-write error explained |
| Zoom H4n via h4n2rs485 | serial COM11, 2400 8N1 | hex, `--lineending None` | handshake test passes; no inbound bytes seen from the raw CLI |

| `00 06 00 00 00 00 00 00 00` and `00 06 01 ...` | same error | accepted, no visible change |

Input stream (unprompted, about 116 reports a second over 9 s, 1049 reports): `00 00 01 28 B5 00 00 00 00` with the analog byte moving between `27`/`28` and `B5`/`B6`.

## Zoom H4n commands

```bash
dotnet test tests/DevTerm.Devices.ZoomH4n.Tests --settings devterm.runsettings
dotnet run --project src/DevTerm.Console -- --transport serial --port COM11 --baud 2400 --presenter hex --parser hex --lineending None --cli true
```

Lines sent: `00` (6 times at 100 ms, then 60 times at 50 ms), `A1 80 00`, `80 01 80 00` (mic). The unit test run passed, 16 of 16, in 32 s. The raw CLI printed nothing back for any of it.

## Findings

- **K8055 write error is the line ending, not the device.** The CLI appends a terminator (default Cr) to every typed line, which made the 9-byte report 10 bytes; Windows HID rejects a wrong-length report. With `--lineending None` the same frames go through. The control panel already sends exact frames.
- **`0x06` has no visible effect.** No error, no change in the stream or its rate. It is not a read command; the board streams on its own.
- Digital output state is not echoed in the input report, so output readback cannot be seen from the stream alone (nothing is wired to the pins).
- **H4n status echo is still unconfirmed.** The test's bar is "no fault, no timeout"; the raw CLI saw zero inbound bytes, so whether this unit answers the wake handshake is still unknown. That needs the recorder's own state change (the screen) watched by a person.

## Summary

No code change. The K8055 hex-send hint belongs in the user guide (use `--lineending None` for fixed-length HID reports).
