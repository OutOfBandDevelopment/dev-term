# 2026-10-03 16:30: Zoom H4n remote port, visual confirmation

Follow-up to `2026-10-03-14-42-02.md`, which left open whether the H4n answers the wake handshake and obeys commands. A person watched the recorder while commands were sent.

## Device matrix

| Device | Transport / address | Framing | Result |
|---|---|---|---|
| Zoom H4n via h4n2rs485 | serial COM11, 2400 8N1, DTR/RTS on | hex presenter, hex parser, `--lineending None` | confirmed working, with caveats |

## Commands

```bash
dotnet run --project src/DevTerm.Console --no-build -- --transport serial --port COM11 --baud 2400 --presenter hex --parser hex --lineending None --cli true
```

Each run piped lines into one session.

| Run | Sent (hex, in order) | Raw replies | Recorder |
|---|---|---|---|
| 1 | `00` x40 (50 ms), `A1 80 00`, `80 01 80 00` twice, 2 s apart | `80` x3 | input was already MIC; nothing visible to change |
| 2 | handshake, then Ch1 `80 02 80 00`, Ch2 `80 04 80 00`, Mic `80 01 80 00`, 5 s apart | none | user had set 1/2 by hand; unclear whether it moved |
| 3 | handshake, `80 01` then `80 00` (150 ms apart) with recorder on 1/2 | none | no change |
| 4 | `00` x200 (30 ms), `A1 80 00`, `80 01`, `80 00` | none | not observed |
| 5 | handshake, `80 02` + `80 00`, 6 s later `80 01` + `80 00` | `80` x3, then `60 80 80`, then alternating `60`/`80` | input switched to MIC |

## Findings

- **The H4n does obey remote commands.** In run 5 the recorder switched to MIC after the Mic press (the Ch2 press just before it was not separately observed).
- **It does answer the handshake**, but not on every attempt. Runs 2 to 4 got no bytes and no effect; runs 1 and 5 got `80` replies. The settings were identical in all runs (and match the saved "Zoom - H4N" profile apart from its COM3 port). Whether the unit needs a replug or fresh power-up, or the earlier runs were just early, is not established. The user had meanwhile used the app on the same port successfully.
- **Status byte stream:** after the Mic press the unit streamed alternating `60` and `80`. By the documented mask that is the Led1/Led2 bits (0x20/0x40) set against none, consistent with a blinking LED, but not mapped to a specific indicator yet.
- Other buttons (record, play, stop): not exercised from the CLI so nothing was recorded. The user reported afterwards that they worked from the app (user-reported, not captured here).

## Summary

No dev-term code change. The "does it respond" question is answered yes for handshake plus Mic. Per-mode LED timing remains open.
