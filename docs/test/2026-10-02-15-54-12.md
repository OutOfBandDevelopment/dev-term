# Busylight bench pass (2026-10-02)

Routine confirm of the Kuando Busylight over USB HID, plus a colour and blink sequence on real hardware.

## Device configuration matrix

| Device | Role | Profile | Transport | Framing | Result |
|---|---|---|---|---|---|
| Kuando Busylight ("BLL Lamp") | presence light | `busylight` presenter / control surface | USB HID, VID 0x04D8 (1240) PID 0xF848 (63560) | 9-byte single-step reports | Confirmed working (observed) |

`--listhiddevices` printed `04D8:F848  BLL Lamp`.

## Commands tested

Through `BusylightControlSurface` against the real device (`RealHardwareBusylightTests`):

| Test | Sent | Result |
|---|---|---|
| `RealDevice_SetColorOffAndApply_...` | color=Off, apply | completed, no fault or timeout |
| `RealDevice_ColorsAndBlink_AllApplyWithoutFaultOrTimeout` (new) | color Red, apply; Green, apply; Blue, apply; blinkMode Fast, color Yellow, apply (first run 0.8 s between steps, second run 2.5 s); then blinkMode Solid, color Off, apply | all sends completed, no fault or timeout; light left off |

Literal commands (from the repo root):

```
dotnet run --project src/DevTerm.Console -- --listhiddevices true
dotnet test tests/DevTerm.Devices.Busylight.Tests --settings devterm.runsettings --filter "FullyQualifiedName~ColorsAndBlink"
```

## Findings

- Observed by the tester on a second run (steps held 2.5 s): the lamp showed red, green, blue, yellow, then off, matching the sequence. Whether the yellow step visibly blinked was not reported, so the fast-blink mode itself is unobserved. On the first run (0.8 s steps) the colours went by too quickly to tell apart, so the hold time in the test is now 2.5 s.
- The device's ASCII identification reply was not exercised.

## Summary

No dev-term code change except the new real-hardware test.
