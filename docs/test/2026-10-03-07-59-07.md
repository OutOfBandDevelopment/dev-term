# LXI discovery and TCP pass: Rigol DG1062Z

Routine confirm of LXI phase 1 (`docs/design/features/lxi-support.md`) against the one LXI instrument on the bench, plus a read-only
SCPI exchange over the TCP transport to the address discovery returned.

## Device matrix

| Device | Role | Profile | Transport | Framing | Result |
|---|---|---|---|---|---|
| Rigol DG1062Z | function generator | `rigol-dg1062z.json` | tcp 192.168.0.87:5555 | ascii, LF | confirmed working, no retry needed |

## Commands

Discovery:

```
dotnet run --project src/DevTerm.Console -- --listlxidevices true
192.168.0.87:5555  Rigol Technologies,DG1062Z,DG1ZA232603118,03.01.12  (192.168.0.87:5555)
```

SCPI (one command per 1.5 s piped to `--transport tcp --host 192.168.0.87 --port 5555 --presenter ascii --lineending Lf --cli true`):

| Sent | Received |
|---|---|
| `*IDN?` | `Rigol Technologies,DG1062Z,DG1ZA232603118,03.01.12` |
| `SYSTem:ERRor?` | `0,"No error"` |
| `:SOURce1:APPLy?` | `"SIN,1.000000E+03,5.000000E+00,0.000000E+00,0.000000E+00"` |
| `:OUTPut1?` | `OFF` |

## Findings

- Discovery returned only the DG1062Z; the other host that answers the portmapper broadcast (192.168.0.67, port 0) was correctly filtered out.
- Piping all commands at once to `--cli true` exits before replies print; pace them (this is the harness, not the device).
- The device answers raw SCPI on 5555, so a VXI-11 client (phase 2) still has no instrument that needs it.

No dev-term change resulted from this pass.
