# K8055 bench pass (2026-10-02)

Routine confirm of the Velleman K8055 over USB HID, plus the first run of the set-outputs commands on real hardware.

## Device configuration matrix

| Device | Role | Profile | Transport | Framing | Result |
|---|---|---|---|---|---|
| Velleman K8055 (jumper position for PID `0x5500`) | I/O board | `k8055` presenter / control surface | USB HID, VID 0x10CF (4303) PID 0x5500 (21760) | 9-byte reports, no terminator | Confirmed working |

Enumerated as `USB\VID_10CF&PID_5500` and `--listhiddevices` printed `10CF:5500`. Only the first of the four boards (K8055-1 in `devterm.runsettings`) is attached; the other three real-hardware cases skip as Inconclusive. The four boards share one code path, so this pass covers all of them.

## Commands and responses

CLI: `dotnet run --project src/DevTerm.Console -- --transport hid --vendorid 4303 --productid 21760 --presenter hex --parser hex --lineending None --cli true`

| Sent (hex) | Meaning | Received / result |
|---|---|---|
| (none) | unprompted input stream | `00000128B500000000`, `00000127B500000000`, `00000128B600000000` (analog inputs floating, as in the 2026-09-15 finding; counters 0) |
| `00 05 0F 80 40 00 00 00 00` | digital out 0x0F, analog out 128 / 64 | accepted, no connection loss |
| `00 03 00 00 00 00 00 00 00` | reset counter 1 | accepted |
| `00 05 00 00 00 00 00 00 00` | all outputs off | accepted |

Through `K8055ControlSurface` (new test `RealHardwareK8055Tests.RealDevice_SetOutputs_AllCommandsCompleteWithoutFaultOrTimeout`, K8055-1): `digitalOut1`=true, `digitalOut3`=true, `analogOut1`=128, `analogOut2`=255, then all four back to off. All eight sends completed with no fault or timeout; outputs are left off. `RealDevice_ResetCounter1_...` also passed.

## Findings

- With `--parser hex` the CLI appends the default line ending to every send, making the report 10 bytes; Windows rejects it ("Operation failed early: The parameter is incorrect") and the session reports a lost connection and reconnects. A HID device needs `--lineending None`. Sending the same 9 bytes with it works.
- Nothing was wired to the board, so the LEDs/outputs weren't observed to change, and the digital inputs and counters weren't exercised. "Accepted" here means the write completed; the physical output state was not checked.

## Summary

No dev-term code change except the new real-hardware test.
