## Write Settings round trip (16:16:38 to 16:16:44)

An inline Python script on COM8 (the same framing as `scripts/radexone_probe.py`, with a Write Settings request built per `RadexOneExtensionCodec`: `02 08 0E 00 05 00 00 00 <alarm> <threshold LE> 00 00 00 <checksum>`). Packet numbers 1 to 10, each reply read after 0.7 s.

| Read Settings, after | query | threshold `14 00` (20), alarm 0 |

The device was left at its original settings (alarm 0, threshold 10). The accumulated counter was untouched (210 before and after). Whether one write is enough, or the 3x repeat is really needed, was not tested; all writes were sent three times.

## Findings

- All nine requests answered on the first try, with the expected lengths (34, 42, 28 bytes).
- Read Data fields moved between passes as a live detector would (ambient 10, 9, 9; CPM 17, 18, 17; accumulated constant at 210), and the checksum bytes tracked them. The units of these numbers were not checked against the device display.
- **Units, one data point:** the user read the device display as **0.12 uSv/h** (user-reported, not timed against a read). Two Read Data reads at 16:15:57 and 16:16:01 gave ambient 11 and 12 (CPM 21 and 17, accumulated 210). 12 matches 0.12 if the raw ambient value is in **0.01 uSv/h** units, and the earlier 9 to 10 fit a drifting background too. A second display reading of **0.14 uSv/h** (user-reported) came while a Read Data at 16:16:44 gave ambient 13, close but not simultaneous. Two points both fit 0.01 uSv/h per count. A single display reading is still not a measurement; a few paired readings (display value and a Read Data at the same moment) would settle it. The code still treats the unit as unknown (`RadexOneReadData.cs`).
- Read Settings decodes (from the documented layout) as alarm setting 0 and threshold 10 (`0A 00`), the same as before. Not cross-checked against the device display.
- The Read Serial/Version reply is binary past its first 4 bytes; there is no readable `SN:` text in it, unlike the doc's worked example. This is the open reserved-byte question; nothing new is established.
- Write Settings works (see above). Not run: Reset Accumulated, which clears the dose counter, and a single (non-repeated) write.

## Summary

No code change. The three read commands are repeatable on the real device.
