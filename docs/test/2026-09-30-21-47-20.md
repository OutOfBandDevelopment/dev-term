# Real-hardware bench test: Tektronix TDS2024 (routine confirm pass)

Routine confirm pass against the Tektronix TDS2024 oscilloscope, brought forward from the normal
queue (ser2net real-server verification deferred, see `BACKLOG.md`) because the unit happened to be
online. Goal: confirm the device still responds as previously verified (`docs/changes/2026-09-25.md`),
not chasing any specific regression.

## Device configuration matrix

| Device | Role | Profile used | Transport + address | Framing | Result |
|---|---|---|---|---|---|
| Tektronix TDS2024 | Oscilloscope | `tektronix-tds2024.json` | TCP (serial-to-Ethernet bridge), `192.168.0.110:23` | `ascii` presenter, `Lf` line ending | Confirmed working |

## Commands tested and responses

Connected via:

```bash
dotnet run --project src/DevTerm.Console -- --transport tcp --host 192.168.0.110 --port 23 --presenter ascii --lineending Lf --cli true
```

| Sent | Received | Notes |
|---|---|---|
| `*IDN?` | `TEKTRONIX,TDS 2024,0,CF:91.1CT FV:v4.12 TDS2CM:CMV:v1.04` | IEEE 488.2 identify, matches prior sessions |
| `ID?` | `ID TEK/TDS 2024,CF:91.1CT,FV:v4.12 TDS2CM:CMV:v1.04` | Tek-code identify, matches prior sessions |
| `CH1?` | `10;1.0E-1;0.0E0;DC;OFF;OFF` | Channel 1 settings query |
| `CH2?` | `10;5.0E-1;0.0E0;DC;OFF;OFF` | Channel 2 settings query |
| `ACQuire?` | `SAMPLE;16;1;RUNSTOP` | Acquisition settings query |

All five replies arrived on the first attempt — no retry needed, and no stale/garbled state from a
prior session. `TRIGger:...?` queries were deliberately not sent, per the known hang quirk tracked in
`BACKLOG.md`'s Tektronix TDS2024 section.
