# TDS2024 alternate hardcopy formats through the Stream Monitor

Real-hardware pass, 2026-10-02: does `HARDCopy:FORMat` give the Stream Monitor other real captures, and do the converters handle them?

## Bench

Tektronix TDS 2024 (`TEKTRONIX,TDS 2024,0,CF:91.1CT FV:v4.12 TDS2CM:CMV:v1.04`) on a serial-to-Ethernet bridge, TCP 192.168.0.110:23, 19200 baud, `WriteByteDelayMs = 50`, `HARDCopy:PORT` RS232. Profile: `tektronix-tds2024.json`.

## Commands

Test `RealHardwareStreamMonitorTests.Tds2024_HardCopy_OtherFormats_AreCaptured`, run with `dotnet test tests/DevTerm.Console.Tests --no-build --filter "Name~OtherFormats" --settings devterm.runsettings`. Per format it sends, over a `Session` with `RawPresenter` and a `StreamMonitor` watching:

```
HARDCopy:FORMat <fmt>

HARDCopy START

```

then restores `HARDCopy:FORMat BMP
`. Afterwards, by CLI: `HARDCopy:FORMat?` -> `BMP`, `HARDCopy:PORT?` -> `RS232`, `*IDN?` -> the string above.

## Results

| Format | Capture | Notes |
|---|---|---|
| EPSIMAGE | "PostScript document", 25,526 bytes, complete, 30 s | Head `%!PS-Adobe-2.0 EPSF-2.0`. Real Ghostscript 10.08 renders a correct 800x1000 PNG of the scope screen; reviewed OK. |
| TIFF | "TIFF image", 13,260 bytes, ended by idle timeout, 18 s | Head `4D4D002A` (big-endian). |
| LASERJET (PCL) | none in 5 minutes | Bug 069. |
| PCX | none in 5 minutes | Bug 069. |

## Findings

- PostScript from a real device now verified end to end: scope, sniffer, Ghostscript.
- LASERJET and PCX never produced a capture; not known whether no bytes arrived or the sniffer did not classify them ([069](../bugs/resolved/069-tds2024-laserjet-pcx-hardcopy-no-capture.md)).
- The default `TestTimeout` (60 s) in `devterm.runsettings` is too short for these captures; the test carries its own `[Timeout]`.
- The scope was left on BMP and still answered `*IDN?`.
