# TDS2024: TRIGger family re-enabled in RealHardwareTcpTests, with write pacing

Confirms the 2026-10-02 finding (`docs/test/2026-10-02-07-01-24.md`) through the automated real-hardware test: the
`TRIGger...?` silence was write pacing, not firmware.

| Device | Role | Profile | Transport | Framing | Result |
|---|---|---|---|---|---|
| Tektronix TDS2024 | scope behind a serial-to-Ethernet bridge | `tektronix-tds2024.json` | TCP 192.168.0.110:23 | LF, `WriteByteDelayMs = 50` | confirmed working |

## Script

```
dotnet test tests/DevTerm.Console.Tests --filter "TestCategory=Tektronix_Tds2024" --settings devterm.runsettings --logger "console;verbosity=detailed"
```

| Sent | Received |
|---|---|
| `*IDN?` | `TEKTRONIX,TDS 2024,0,CF:91.1CT FV:v4.12 TDS2CM:CMV:v1.04` |

No retry was needed. Test passed in 2 s. All four are read-only.

## Summary

`RealHardwareTcpTests` now sends `TRIGger:STATE?` with `WriteByteDelayMs = 50`. No production code changed.
