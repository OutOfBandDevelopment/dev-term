Writes were read back correctly. Source 1 was 5 V / 1 kHz before the pass, was changed to 2 kHz / 1.5 V, then to 1 kHz / 1 V by mistake instead of 5 V. It was restored afterwards (`:SOUR1:VOLT 5`, read back `5.000000E+00`, frequency `1.000000E+03`, error queue clean). Output stayed OFF throughout.

Separate sessions:

- Three runs of `*IDN?`, `*IDN?`, `:SYST:ERR?` (1 s apart): every reply correct, `0,"No error"` each time.
- Rapid-fire, six lines with no sleeps: all six answered in order.
- Five connect, `*IDN?`, disconnect cycles: 5 of 5 returned the DG1062Z identity.

## Findings

- In the long session the first `*IDN?` got no reply and the error queue then held `-410 Query INTERRUPTED`. The cause is not established (a query sent before the link settled, or an `*OPC?` arriving while the `*IDN?` was pending). It did not recur: the three-run, rapid-fire and reconnect sessions all answered `*IDN?` correctly. Treat it as an unresolved one-off to watch, not a confirmed fault.
- An unknown query (`:BOGUS:CMD?`) yields an empty reply and queues error -113, as expected from the instrument.
- The instrument was left as found (5 V, 1 kHz, output OFF).

## Summary

No dev-term code change. VXI-11 is verified for queries, writes, the error queue, back-to-back sends and reconnects against one instrument. device_clear, the status byte, SRQ and locking remain unbuilt.
