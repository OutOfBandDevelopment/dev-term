# Stream Monitor bench pass: DG1062Z screen dump and TDS2024 hard copy

2026-10-02. Checks the Stream Monitor (`StreamMonitor` over a real `Session`) against two real instruments'
image output, the two checks `docs/design/proposals/stream-content-detection.md` listed as unverified.

## Device matrix

| Device | Transport | Command | Result |
|---|---|---|---|
| Rigol DG1062Z (SN DG1ZA232603118) | USBTMC `1AB1:0642` | `HCOPy:SDUMp:DATA?` | Confirmed working |
| Tektronix TDS2024 | TCP 192.168.0.110:23 (19200 baud bridge, 50 ms write delay) | `HARDCopy START` | Confirmed working |

## Commands and replies

DG1062Z, first through the CLI to see the raw reply:

```bash
(sleep 1; echo 'HCOPy:SDUMp:DATA?'; sleep 8) | dotnet artifacts/console/DevTerm.Console.dll --transport usbtmc --vendorid 6833 --productid 1602 --serialnumber DG1ZA232603118 --presenter hex --parser ascii --lineending Lf --cli true
```

Reply began `2339303030323330343536424D3684030000000000360000002800000040010000F0000000010018...`
(`#9000230456` then `BM`, 320x240, 24-bit), the whole message in one reply.

TDS2024 settings, read first (CLI, `--presenter ascii --lineending Lf --writebytedelayms 50`):
`HARDCopy:FORMat?` -> `BMP`, `HARDCopy:PORT?` -> `RS232`, `HARDCopy:LAYout?` -> `PORTRAIT`.

Then both through the Stream Monitor, as real-hardware tests (`RealHardwareStreamMonitorTests`):

```bash
dotnet test tests/DevTerm.Console.Tests --filter "FullyQualifiedName~RealHardwareStreamMonitorTests" --settings devterm.runsettings
```

| Test | Capture |
|---|---|
| `Dg1062z_ScreenDump_IsCapturedAsOneBmp` | `Kind=BMP image Bytes=230456 End=Complete`, saved `DG1062Z_20261002-181004.bmp` (253 ms) |
| `Tds2024_HardCopy_IsCapturedAsOneBmp` | `Kind=BMP image Bytes=77878 End=Complete`, saved `TDS2024_20261002-181111.bmp` (44 s) |

## Findings

- The DG1062Z's `#9000230456` header is stripped and the file is the bare BMP, as the spec says.
- The TDS2024 hard copy has no SCPI header; the BMP signature and its own length end the capture (`Complete`,
  not `went quiet`). It takes about 44 s at 19200 baud.
- Nothing needed fixing in dev-term.
