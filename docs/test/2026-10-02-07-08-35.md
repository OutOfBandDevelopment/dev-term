## Findings

- **A block reply can never land on the boundary, so the missing-ZLP check needs a different kind of reply.** A
  bulk-IN transfer is a 12-byte USBTMC header plus the payload, padded to a multiple of 4. An IEEE block reply is
  `#8` + 8 digits (10 bytes) + N data bytes. For every N the scope has produced so far (600 in normal mode, 8192 in
  RAW/long, and the other power-of-two memory depths) the transfer is N + 12 + 10 + 2 pad = N + 24 bytes, which is
  24 mod 64 for any N that is a multiple of 64, so it never hits a multiple of 64. This is arithmetic from the
  observed 610-byte and 8202-byte replies, not something measured on the wire; it assumes the 2-byte pad seen in the
  earlier bench report. To test the edge case the reply needs a payload of 52 or 116 bytes (or 52 + 64k), i.e. a
  text query whose length can be steered, or a block with N = 64k - 34 samples.
- The two earlier attempts (610 and 8202 bytes) were consistent with this: they could not have hit it.

## Summary

No dev-term code changed. BACKLOG's missing-ZLP item now notes why block replies cannot reach the boundary and what
kind of reply could. The edge case is still unreproduced.
