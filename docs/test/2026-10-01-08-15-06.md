# Real-hardware test: Zoom H4n remote (RC04/RC2, via h4n2rs485 adapter)

First real-hardware confirmation for `DevTerm.Devices.ZoomH4n`, implemented 2026-09-25 but not
previously run against a live unit (`devterm.runsettings`' `RealSerialZoomH4nPort` had only an
unconfirmed COM3 guess). The adapter is now attached and enumerated as COM5.

## Bench topology

Zoom H4n recorder --(RC04/RC2 4-pin TRRS)--> `h4n2rs485` adapter --(USB)--> this machine, COM5.

## Device configuration matrix

| Device | Role | Profile/module | Transport+address | Framing | Result |
|---|---|---|---|---|---|
| Zoom H4n | Portable recorder, remote control | `DevTerm.Devices.ZoomH4n` | Serial, COM5 | 2400 8-N-1, no handshake | Confirmed working |

## Commands tested and responses

Ran via `dotnet test tests/DevTerm.Devices.ZoomH4n.Tests --filter "FullyQualifiedName~RealHardwareZoomH4nTests" --settings devterm.runsettings`
after updating `devterm.runsettings`' `RealSerialZoomH4nPort` from `COM3` to `COM5` (the port the
adapter is actually attached to today).

| Step | Sent | Result |
|---|---|---|
| Open | — | Connection opened without fault. |
| Init handshake | `0x00` repeated (internal, up to 1024×) then wake sequence `0xA1 0x80 0x00` | Ran automatically inside `ZoomH4nControlSurface.InvokeAsync`; no fault/timeout. |
| Button command | `mic` (`0x80 0x01` then release `0x80 0x00`) | Sent without fault or timeout. |
| Close | — | Connection closed without fault. |

Test result: **Passed** (`InvokeAsync_AgainstRealDevice_CompletesHandshakeAndSendsAButtonCommand`,
607 ms).

Per this test's own documented bar (see its class doc comment in
`tests/DevTerm.Devices.ZoomH4n.Tests/RealHardwareZoomH4nTests.cs`), this only proves the init
handshake completes and a command sends without the device rejecting it or the connection
faulting — not all 12 buttons, and not the exact wire-level reply content (the H4n's remote port
is send-oriented; whether it echoes anything observable back for this physical unit still isn't
confirmed).

## Findings

- The adapter's COM port changed from COM3 (reported 2026-09-25) to COM5 — Windows reassigns these
  on replug, as already noted for other serial devices on this bench. `devterm.runsettings`
  updated accordingly.
- No other quirks observed: the handshake-then-command path matched the implementation's
  assumptions on the first attempt, no retry needed.

## Summary

`docs/design/proposals/zoom-h4n-remote-protocol.md`'s Status updated to "implemented and verified
against real hardware," and the proposal moved to `docs/design/features/` per this repo's own
convention (`docs/design/README.md`'s Features section: proposals move out of `proposals/` once
completed *and* verified, not merely completed). `devterm.runsettings`' `RealSerialZoomH4nPort`
updated from `COM3` to `COM5`.
