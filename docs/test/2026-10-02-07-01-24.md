# Bench test 2026-10-02 07:01:24 - Tektronix TDS2024, TRIGger queries with a 50 ms write-byte delay

A focused re-check of the long-standing "every `TRIGger...?` query gets no reply" finding
(`docs/test/2026-09-25-18-57-22.md`, `docs/test/2026-09-30-21-51-12.md`, BACKLOG.md's "Tektronix TDS2024"
item), after the user observed that pacing writes byte by byte makes the query answer.

## Device configuration matrix

| Device | Role | Profile | Transport / address | Framing | Result |
|---|---|---|---|---|---|
| Tektronix TDS2024 (TDS2CMAX RS-232 module, FV:v4.12) | Oscilloscope | `tektronix-tds2024.json` | TCP, `192.168.0.110:23` (serial-to-Ethernet bridge) | LF, ascii presenter, `--writebytedelayms 50` | `TRIGger:STATE?` replied; previously never did |

## Commands tested and responses

Command line:

```bash
printf '*IDN?\nTRIGger:STATE?\nTRIGger:STATE?\n' | dotnet run --project src/DevTerm.Console -- \
  --transport tcp --host 192.168.0.110 --port 23 --writebytedelayms 50 \
  --presenter ascii --lineending Lf --cli true
```

## Findings

- **The missing-reply symptom is a write-pacing problem, not a firmware refusal.** With
  `--writebytedelayms 50` the `TRIGger` family answers. The user's reading, which fits this result: the
  device (or its bridge) has no input FIFO, so a command written as one burst loses bytes. The
  `TRIGger` queries were the visible casualty, probably because their header is long. This overturns
  the BACKLOG hypothesis that the unit needs TDS2024B firmware.
- **The bridge holds a reply across a disconnect/reconnect.** The first line above answers a command
  from an earlier connection and surfaced on this one, ahead of the new connection's own replies. When
  scripting against this bridge, a reply that doesn't match the command just sent is a stale one.
- The earlier "`CH1?`/`CH2?` instead of `TRIGger`" workaround in `RealHardwareTcpTests` can be revisited
  with the delay enabled; not done in this session.

## Summary

No dev-term code changed. The TDS2024's connection profile needs `WriteByteDelayMs` set (50 worked) and
the device profile's `Notes` now says so. BACKLOG.md's TDS2024 item is resolved by this finding.
