## Findings

- **Earthmate BT-20's fix status (`V`) is void** in the decoded `$GPRMC` sentence — expected, the
  unit has no satellite lock in this indoor location. This is a valid, correctly-decoded sentence,
  not a device or decoder fault; the test only asserts a sentence decodes, not that it has a fix.
- Everything else behaved exactly as already documented — no surprises on Busylight or K8055.

## Summary

No code change. This confirms the Earthmate BT-20 GPS module (`DevTerm.Devices.Nmea`) for the first
time against real hardware — its HID framing assumption, undocumented as verified since it was built
