# 2026-10-03 19:00: Kuando Busylight on/off time units (observed by the user)

The single 8-byte step's On and Off bytes had unknown units (design doc open question). The user watched the lamp while steps were sent; nothing was timed.

## Device

Kuando Busylight, USB HID VID 0x04D8 / PID 0xF848 (1240 / 63560).

## Commands

```bash
dotnet run --project src/DevTerm.Console --no-build -- --transport hid --vendorid 1240 --productid 63560 --presenter hex --parser hex --lineending None --cli true
```

Nine-byte frames, `00 00 00 FF 00 00 <On> <Off> 00` (report id, NextStep 0, Repeat 0, R=FF, G=0, B=0, audio 0). The device also streams its 64-byte ASCII identification report back unprompted while open (it repeated the same bytes every time).

| Run | Sent (On/Off, hex) | Sent at | User observed (user-reported) |
|---|---|---|---|
| 1, 6 s apart | `01 00` solid, `0A 0A`, `01 01`, `32 32`, `05 14`, then all zeros | 16:08:35 to 16:09:05 | "red", "red blink slow then fast", "red solid", "red flash several times" (the messages arrived out of step with the sends, so no one-to-one mapping) |
| 2, 10 s apart | `32 32` (50/50), `05 14` (5/20), `01 01` (1/1), then all zeros | 16:09:26, :36, :46, :56 | "red", "red flash", "red fast flash" |

## Findings

- The observations are consistent with On/Off in **100 ms units**: 10/10 a slow blink and 1/1 a fast one, 5/20 a short flash with a long gap, 50/50 (5 s on) reading as plain red inside a 10 s window. Not timed against a stopwatch and the first run's mapping was ambiguous, so this is a strong hint, not a measurement.
- No fault, no unexpected reply; the lamp was left off (all-zero step).
- The batch/program-mode write was not retried in this session.

## Summary

No code change. Proposes 100 ms units for the On/Off bytes; a timed check (a phone video or a stopwatch on one blink) would confirm it.
