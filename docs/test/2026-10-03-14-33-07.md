# 2026-10-03 14:33: VXI-11 transport against the Rigol DG1062Z

Checks the new `vxi11` transport ([design](../design/vxi11-transport.md)) against a real LXI instrument.

## Device matrix

| Device | Transport / address | Framing | Result |
|---|---|---|---|
| Rigol DG1062Z (LXI) | `vxi11`, 192.168.0.87 (portmapper TCP 111, then the core port it returns) | ascii presenter, LF | confirmed working |

## Commands

```bash
dotnet test tests/DevTerm.Transports.Vxi11.Tests --filter "TestCategory=Hardware"
dotnet run --project src/DevTerm.Console -- --transport vxi11 --host 192.168.0.87 --presenter ascii --lineending Lf --cli true
```

Lines piped to the CLI, with a short sleep between them (the transport answers each as its own device_read):

| Sent | Raw reply |
|---|---|
| `*IDN?` | `[ascii] Rigol Technologies,DG1062Z,DG1ZA232603118,03.01.12` |
| a frequency query (source 1) | `[ascii] 1.000000E+03` |

The hardware unit test (`RealHardwareVxi11Tests`) sent `*IDN?` with `AppendLineFeedAtEnd = false` and asserted the reply contains `DG1062Z`; it passed.

## Findings

- The DG1062Z ends its reply with LF itself, so the transport's append-LF fallback is not needed for it.
- No `--port` is needed; the portmapper lookup works. Nothing was changed on the instrument (read-only queries).

## Summary

No dev-term change resulted beyond the new transport itself.
