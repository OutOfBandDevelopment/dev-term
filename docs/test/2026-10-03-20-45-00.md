# 2026-10-03 20:45: DG1062Z screen capture over USBTMC

Closes the "USB path not recorded" gap from `2026-10-03-18-30-00.md` (the VXI-11 capture).

## Device matrix

| Device | Transport / address | Framing | Result |
|---|---|---|---|
| Rigol DG1062Z | `usbtmc`, VID 0x1AB1 (6833), PID 0x0642 (1602), serial DG1ZA232603118 | hex presenter, ascii parser, `--lineending Lf` | confirmed working |

`--listusbtmcdevices true` also listed a DM3000 (DM3R232301438), DS1000 (DS1ET180300759) and DG3000 (DG1D125306284) on the same hub; only the DG1062Z was used.

## Command

```bash
(echo '*IDN?'; sleep 2; echo 'HCOPy:SDUMp:DATA?'; sleep 15) | dotnet run --project src/DevTerm.Console --no-build -- --transport usbtmc --vendorid 6833 --productid 1602 --serialnumber DG1ZA232603118 --presenter hex --parser ascii --lineending Lf --cli true
```

## Raw replies

| Sent | Reply |
|---|---|
| `*IDN?` | `Rigol Technologies,DG1062Z,DG1ZA232603118,03.01.12` |
| `HCOPy:SDUMp:DATA?` | IEEE 488.2 block `#9000230456` then 230,456 bytes (230,468 total with the header) |

The payload is a valid BMP: declared size 230,454 (2 less than the block length, as over VXI-11), 320x240, 24-bit; Pillow opened it. The hex lines were joined and decoded as in the earlier captures.

## Findings

- The USBTMC path returns the same screen image as VXI-11, in one reply, with no framing difference.
- The sent device state was not changed; this is a read-only query.

## Summary

No code change. The DG1062Z screen capture is now verified over both VXI-11 and USBTMC.
